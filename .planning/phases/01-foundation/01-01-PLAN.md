       ```swift
       enum AutomationStatus: Equatable {
           case idle
           case running
           case success
           case error(String)
       }
       ```

    3. Create `PandaAutomator/Engine/JSBridgeHandler.swift`:
       - Class conforming to `NSObject, WKScriptMessageHandler`
       - `userContentController(_:didReceive:)` receives messages on the "log" channel
       - Holds a closure `var onLog: ((String) -> Void)?` to forward messages to ViewModel
       - Annotated `@MainActor`

    4. Create `PandaAutomator/Engine/AutomationEngine.swift`:
       - `@MainActor class AutomationEngine: NSObject, WKNavigationDelegate`
       - Private `WKWebView!` property
       - Private `JSBridgeHandler` property
       - `func setup()` method that:
         a. Creates `WKWebViewConfiguration` with `WKUserContentController`
         b. Adds anti-detection `WKUserScript` at `.atDocumentStart`:
            `Object.defineProperty(navigator, 'webdriver', { get: () => undefined });`
            `Object.defineProperty(navigator, 'plugins', { get: () => [1, 2, 3] });`
         c. Registers JSBridgeHandler on "log" message name
         d. Creates `WKWebView(frame: .zero, configuration: config)`
         e. Sets `webView.navigationDelegate = self`
         f. Sets `webView.customUserAgent` to clean Mobile Safari string:
            `"Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.0 Mobile/15E148 Safari/604.1"`
         g. Attaches to `UIWindowScene` window: `scene?.windows.first?.addSubview(webView)` using `connectedScenes` API (NOT deprecated `UIApplication.shared.windows`)
       - `func loadFeedbackPage()` that loads `https://www.pandaexpress.com/feedback`
       - `var onLog: ((String) -> Void)?` property wired through to JSBridgeHandler
       - Stub `func run(code: String, email: String)` that calls `loadFeedbackPage()` (Phase 2 fills in the real logic)
       - `webView(_:didFinish:)` delegate method that calls `onLog?("Page loaded")`

    5. Update `PandaAutomatorApp.swift` to use SwiftUI App lifecycle with a simple placeholder ContentView (just Text("Panda") for now — Plan 02 builds the real UI).

    IMPORTANT: Use `ObservableObject` with `@Published` (NOT `@Observable`) because deployment target is iOS 16.0. `@Observable` requires iOS 17+.

    IMPORTANT: Call `engine.setup()` from the view's `onAppear`, NOT from `init()`, because `UIWindowScene` may not be connected yet at init time.

  <name>Task 2: Create AutomationViewModel with validation, state management, and email persistence</name>
  <files>

  <action>
    Create `PandaAutomator/ViewModel/AutomationViewModel.swift`:

    - `@MainActor class AutomationViewModel: ObservableObject` (NOT @Observable — iOS 16 target)
    - Properties:
      - `@AppStorage("savedEmail") var email: String = ""` — persists email across launches (FORM-02)
      - `@Published var surveyCode: String = ""` — raw input with dashes for display
      - `@Published var isRunning: Bool = false` — locks inputs when true (FORM-04)
      - `@Published var showLogs: Bool = false`
      - `@Published var logMessages: [String] = []`
      - `@Published var status: AutomationStatus = .idle`
    - Computed properties:
      - `var cleanCode: String` — strips dashes from surveyCode (FORM-01 support)
      - `var isValid: Bool` — `cleanCode.count == 24 && email.contains("@") && email.contains(".")` (FORM-03)
    - Private `let engine = AutomationEngine()`
    - `func setupEngine()` — calls `engine.setup()` and wires `engine.onLog` to `appendLog(_:)`. This is called from the view's `onAppear`.
    - `func startAutomation()` — guard `isValid`, set `isRunning = true`, `status = .running`, call `engine.run(code:email:)`
    - `func appendLog(_ message: String)` — appends to `logMessages`
    - `func formatCodeWithDashes(_ input: String) -> String` — strips dashes, keeps first 24 alphanumeric chars uppercased, reinserts dash every 4 chars. Returns formatted string. This is called from the view's `onChange` of surveyCode.

    Note on @AppStorage + ObservableObject: `@AppStorage` does not automatically trigger `objectWillChange` on `ObservableObject`. Workaround: use a private `@AppStorage` backing and a `@Published var email` that syncs to UserDefaults manually in `didSet`, OR use `@Published` and read/write `UserDefaults.standard` directly. Choose the simplest working approach.
